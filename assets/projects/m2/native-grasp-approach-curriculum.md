# Training grasp acquisition from an audited reset distance

The new distance curriculum is implemented and **disabled by default**. It
changes where the robots start a training episode. The actor still decides
whether to approach, close, lift, wait, and move. It receives no curriculum
stage, teacher label, partner-ready message, or action gate.

Native-contact grasp success is still unresolved. This mechanism has passed
software tests; it has not demonstrated a trained >90% grasp success rate.
Static alignment and a scripted grip are separate physical diagnostics.
In particular, the geometry audit found that a successful thumb/pinky pinch
can have zero palm-body support force, and naive near starts can overlap the
rail before the first policy action.
[Geometry evidence](RL_NATIVE_GRASP_GEOMETRY_AUDIT.md).

## Configuration and promotion

All settings live under `training.approach_distance_curriculum`. The serialized
default contains only the full 4–10 cm approach range:

```json
{
  "enabled": false,
  "ranges_m": [[0.04, 0.10]],
  "initial_level": 0,
  "maximum_standoff_m": 0.10,
  "window_episodes": 100,
  "minimum_episodes_per_level": 100,
  "promote_success_rate": 0.90,
  "reset_domain_version": "",
  "reset_feasibility_report": null
}
```

A future enabled experiment can prepend audited near-distance intervals. Their
lower and upper bounds must increase monotonically; the final upper bound must
reach `maximum_standoff_m`. The promotion threshold cannot be set below 0.90.
The near intervals must come from actual open-hand reset and dynamics tests;
they must not be inferred from visual alignment alone.

The schedule counts one outcome per **completed environment episode**, covering
both robots. With the default window, 90/100 successes does not promote;
91/100 does. A complete window and at least 100 completed episodes at the current
level are required. After promotion the window clears. An episode already
running at an earlier distance retains its original tag and cannot count toward
the harder level. There is no automatic demotion or change to reward weights.

Only the next `env.reset()` applies a promoted range. Joint states and actions
in an ongoing episode are untouched. Noise and contact schedules remain
independent. Current support is the serial native-contact recovery vector;
process vectors and radial-spawn overrides reject an enabled distance schedule.

## Reset geometry must be proven separately

`environment.acquisition.reset_pregrasp_clearance_m` is a separate, default-zero
reset parameter. It lowers the cached pregrasp IK target, while the final hand
targets from the planner stay unchanged. It requires native contacts and an
open-grasp initial stage, and is constrained to 0–0.10 m. A nonzero value is an
experimental reset geometry change, not a learned lift or a grasp attachment.

Before an enabled curriculum starts, the trainer reads its feasibility report.
The report must be complete, explicitly valid, and match `reset_domain_version`.
A matching variant must declare:

- `safe_open_reset: true`, with evidence from the actual physical reset tests;
- the exact `grasp_palm_below_bar_m` and `grasp_palm_forward_offset_m`;
- `reset_domain_sha256`, generated by the shared helper from the full resolved
  environment configuration, excluding only the worker seed and scheduled
  standoff interval;
- `audited_standoff_ranges_m`, covering every training interval without gaps,
  or one `training_standoff_m` interval covering the whole schedule.

The fingerprint therefore includes object randomization, mass, friction,
heading variation, reset hand clearance, task settings and dynamics settings.
Changing these invalidates the proof. The finite audit establishes evidence
for its tested samples; it does not mathematically certify every continuous
initial condition. Failed reset/physics trials must remain visible.

## Checkpoints and independent evaluation

Checkpoints save the exact curriculum configuration, current level, rolling
outcomes, episode counts, promotion history and the feasibility report hash.
Resume rejects changed settings, incompatible geometry proof, or missing
progress from a previously enabled curriculum. A legacy checkpoint with no
distance schedule may initialize a newly declared schedule with an empty
window at its initial level, preserving actor, critic and Adam state.

Training episode logs include the actual applied interval and level; PPO metrics
include the current training window count. These are **training evidence**.
The frozen acquisition suite separately declares `approach_standoff_m:
[0.04, 0.10]`. The benchmark applies that range after other domain overrides,
disables the training schedule, and records it in top-level and per-trial
`evaluation_domain` plus the actual per-trial configuration. An enabled
training curriculum with no explicit evaluation range is rejected.

No easier training start can improve a reported full-approach score merely by
changing the evaluation starts. The acquisition suite remains a grasp/lift/hold
screen; it does not establish doorway, pitch-control, transport or release
recovery success.

## Verification and implementation

The combined configuration and curriculum suite passed 76 tests, including
strict 90% boundary cases, unfinished/stale episode exclusion, checkpoint and
Adam restoration, incompatible-state rejection, audit coverage/fingerprint
checks, reset-boundary application and fixed full-range evaluation. These tests
allocate no additional MuJoCo workers. They validate software behavior, not the
physical success of a trained policy.

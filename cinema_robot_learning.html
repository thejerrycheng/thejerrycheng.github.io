PyTorch · CVAE · ACT

Robot Learning

Visuomotor imitation learning from kinesthetic demonstrations. Three model architectures evaluated end-to-end on real IRIS hardware.

⚙ Training Code 📄 Read the Paper
Architecture

Three model variants.

We evaluate three imitation learning architectures on the same kinesthetic demonstration dataset. Models share the same ResNet-34 visual encoder backbone; the action head differs across variants.

CVAE / ACT

Primary model · Action Chunking
Primary

Conditional Variational Autoencoder with a Transformer decoder that predicts a chunk of F=15 future actions at once. Latent variable z encodes multi-modal action distribution from demonstrations.

CVAE Transformer Latent z
  • Input: S=8 frame window + current joint state + goal image
  • Output: F=15 future joint angle targets
  • Loss: MSE + KL divergence + smoothness term
  • Latent dim: 32 | β: 0.01

Deterministic Transformer

No latent variable
Baseline

Transformer-based sequence-to-sequence model without a latent variable. Ablates the stochastic component of the CVAE to measure the contribution of latent variable modeling.

Transformer Deterministic
  • Input: S=8 frame window + current joint state + goal image
  • Output: F=15 future joint angle targets
  • Loss: MSE + smoothness term
  • No latent variable (z removed)

CNN-BC

Behavior Cloning baseline
Baseline

ResNet-34 + MLP behavior cloning baseline. Single-step prediction without action chunking. Provides a lower-bound on sequence modeling capability.

ResNet-34 MLP
  • Input: single RGB frame + current joint state
  • Output: next-step joint angle targets
  • Loss: MSE
  • No temporal modeling

Model Naming Convention

Model variants are named as {arch}_{obs} where arch ∈ {cvae, det, vanilla_bc} and obs ∈ {rgb (image only), visual (+goal image), full (+joint history+goal)}. The primary model is cvae_full.

Dataset

Episode Format & Structure

Demonstrations are collected via kinesthetic teaching on real IRIS hardware and stored as ROS bags, then processed into episodes. Each episode captures synchronized RGB, depth, and joint states.

Window Size (S)
8 frames
Input observation history
Horizon (F)
15 steps
Predicted future actions
RGB Resolution
640×480
Center-cropped, normalized
Control Dim
6
Joint angles (radians)

Episode Directory Layout

processed_data/
└── demo_YYYYMMDD_HHMMSS_episode_XXXX/
    ├── rgb/
    │   └── frame_0000.png  # 640×480 RGB
    ├── depth/
    │   └── frame_0000.png  # 16-bit depth
    ├── robot/
    │   └── joint_states.csv  # timestamp, pos×6, vel×6, eff×6
    └── meta.json             # num_frames, t_start, t_end

The EpisodeWindowDataset class (datasets/iris_dataset.py) handles windowed sampling, normalization, and train/val/test splits.

Training

Training Commands

All training scripts support auto-resume — rerun the same command to continue from the last checkpoint. GPU recommended (~8 hours on RTX 4090 for 100 epochs).

CVAE (Primary Model)

python train_cvae.py \
  --name MY_RUN \
  --model cvae_full \
  --loss loss_kl \
  --data_roots ~/Desktop/final_RGB_joint_goal \
  --checkpoint_dir ~/Desktop/checkpoints \
  --batch_size 64 \
  --num_workers 8 \
  --epochs 100 \
  --latent_dim 32 \
  --beta 0.01

Deterministic Transformer

python train_determinstic.py \
  --name MY_RUN \
  --model det_rgb \
  --loss mse_smooth \
  --data_roots ~/Desktop/final_RGB_only \
  --checkpoint_dir ~/Desktop/checkpoints

CNN-BC Baseline

python train_cnn_bc.py \
  --name MY_RUN \
  --data_roots ~/Desktop/final_RGB_joint_goal \
  --checkpoint_dir ~/Desktop/checkpoints

Offline Evaluation

python metrics_test.py \
  --test_data ~/Desktop/final_RGB_joint_goal/test \
  --checkpoint ~/Desktop/checkpoints/best_cvae_full_v1.pth \
  --model_type cvae_full
Deployment

Policy Deployment

Deploy a trained policy to the real robot. The policy node reads from the RealSense camera and publishes joint commands via the ROS hardware driver.

Real Robot Deployment

# Deploy CVAE policy to real hardware
cd ~/IRIS/il_training
python policy.py \
  --model_type cvae_full \
  --checkpoint ~/Desktop/checkpoints/best_cvae_full_v1.pth \
  --stats_path ~/Desktop/final_RGB_joint_goal/dataset_stats.pkl \
  --device cuda \
  --real_robot \
  --vis    # optional: live camera overlay

The --stats_path flag is required at inference to un-normalize robot actions back to joint angles. Generated automatically during dataset processing.

Simulation Deployment

# Deploy in MuJoCo simulation (no --real_robot)
python policy.py \
  --model_type cvae_full \
  --checkpoint ~/Desktop/checkpoints/best_cvae_full_v1.pth \
  --stats_path ~/Desktop/final_RGB_joint_goal/dataset_stats.pkl \
  --device cpu

Simulation deployment uses the MuJoCo physics model with the same policy interface as real hardware. Ideal for validating policies before deploying to the robot.
